# 예매처 간 식별 결합: 구현하지 않음

상태: 결정 고정. 구현하지 않는다. 이 문서는 법률 자문이 아니며, 향후 검토는 법무 검토를 거친다.

## 결정

Ticket Defender는 서로 다른 예매처(공급자 namespace, tenant)의 계정, 예매, 신호 토큰을 결합해 하나의 후보나
군집을 만들지 않는다. 같은 예매처 안에서도 HMAC 목적이나 키 버전이 다른 토큰은 잇지 않는다. 다회차 조사
실행은 하나의 공급자 namespace, `TRACK1_CONNECTION` 목적, 하나의 키 버전만 받는다.

## 이유

1. 개인정보 보호법 제17조(개인정보의 제공): 예매처가 수집한 개인정보를 다른 예매처와의 결합 목적으로
   제3자에게 제공하려면 정보주체 동의 등 법정 요건이 필요하다. 예매처별 HMAC 토큰을 다른 예매처 데이터와
   맞대어 보는 것은 실질적으로 이런 제공과 결합에 해당할 수 있다.
2. 같은 법 제18조(개인정보의 목적 외 이용, 제공 제한): 예매처가 자기 서비스의 부정 예매 대응을 위해
   맡긴 데이터를 다른 예매처의 조사에 쓰는 것은 수집 목적 밖의 이용이 될 수 있다.
3. 같은 법 제28조의3(가명정보의 결합 제한): 서로 다른 개인정보처리자 사이의 가명정보 결합은 지정된
   결합전문기관을 거쳐야 한다. HMAC 토큰은 가명정보로 볼 수 있으므로 이 서비스가 직접 결합할 근거가 없다.

## 결합을 막는 구조

- `TenantPurposeReferenceHasher`는 tenant, 목적, 키 버전으로 파생한 키로 HMAC을 계산한다. 같은 원본
  값이라도 예매처가 다르면 다른 토큰이 되므로, 토큰을 맞대어도 예매처 간 일치가 생기지 않는다.
- 신호별 목적(`TRACK1_SIG_DEVICE` 등)도 분리되어 같은 문자열의 기기 토큰과 배송지 토큰이 다르다.
- 다회차 실행 생성은 공급자 namespace가 섞이면 `MULTI_EVENT_SUPPLIER_MIXED`, 신호 행의 목적이나 키 버전이
  하나가 아니면 `MULTI_EVENT_IDENTITY_CONTRACT_UNAVAILABLE`로 거절한다. Data도 요청과 artifact manifest에서
  같은 조건을 다시 검사하고 `identity_contract_mixed`, `SUPPLIER_NAMESPACE_MIXED`, `HMAC_KEY_VERSION_MIXED`로
  거절한다. 이 차단은 `MultiEventMultiPerformanceTest`와 Data의 다공연 테스트가 회귀로 지킨다.
- 키 버전을 바꾸면 이전 버전 토큰과 연결되지 않는다. 이 성질은 결합 방지에도 쓰인다.

## 향후 검토 순서

결합이 필요하다는 요구가 생기면 아래 순서로 검토하며, 각 단계는 법무 검토와 계약을 전제로 한다.

1. 위협 정보 공유: 개인 식별 결합 없이 공격 기법, 자동화 도구 지표, 집계 통계만 예매처 사이에 공유한다.
2. 신고기관 경유: 예매처가 각자 조사한 결과를 수사기관이나 관계 기관에 신고하고, 결합 판단은 법적 권한이
   있는 기관이 한다.
3. 규제 샌드박스: 결합전문기관을 통한 가명정보 결합이나 실증 특례를 받아, 승인된 범위에서만 시험한다.

어느 단계도 이 저장소의 자동 기능으로 열지 않는다. 운영 설정이나 코드 변경 전에 별도 계약과 승인 기록이
필요하다.
