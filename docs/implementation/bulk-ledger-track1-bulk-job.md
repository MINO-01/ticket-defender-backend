# Bulk Ledger Track 1 / Data job contract

`ticket-defender.bulk-ledger-track1.bulk.enabled=false` is the default. When explicitly enabled for synthetic, isolated operation, Spring fixes one published ledger version, writes UTF-8 `track1-limit-ndjson-v1` to a private versioned S3 object, and registers its immutable manifest with Data `POST /api/v2/clusters/jobs`.

The manifest uses the real S3 VersionId, SHA-256, count, ledger generation/revision, source version/as-of, `TRACK1_CONNECTION` purpose and one HMAC key version. Missing/mixed lineage, source, signal purpose/key version, or policy-bundle version leaves the job `BLOCKED`; no invented policy or netting state is sent. `CHANGE_FEED` remains `NOT_CONFIRMED` for cancellation handling.

Spring owns `PREPARING`, `REGISTERING`, `QUEUED`, `RUNNING`, `COLLECTING`, `COMPLETED`, `RETRYABLE`, `FAILED`, and `BLOCKED`; Data's state is stored separately. HTTP/S3 calls run outside transactions. Cluster, shared-observation, evaluation and per-performance finding cursor checkpoints make page writes repeatable. Completion requires every cluster/member page, both opt-in auxiliary page types, every `EVALUATED` performance's finding pages, and the stored finding count to match Data's declared count. A dependency/contract failure preserves the last cursor and never becomes a zero-result completion.

Before artifact upload, a streaming pass fixes `td_bulk_ledger_track1_policy_snapshots`: actual policy ID/revision/version/effective period, ledger version/source/as-of, FULL_SNAPSHOT suitability, NETTED/GROSS rule, and quantity verification result. The persisted snapshot, not a digest or configuration string, is the authority for a confirmed scope. Its randomly generated UUID only identifies the stored immutable snapshot bundle in the Data manifest; it is not a content digest or proof of the policy. Retries load it and never reselect the current ACTIVE policy. A confirmed internal `GROSS` rule remains preserved in that snapshot, but Data receives `POLICY_NOT_CONFIRMED`, `INCOMPLETE`, `NOT_CONFIRMED`, and `GROSS_RULE_NOT_SUPPORTED`; Data is never told that GROSS is supported. If ACCOUNT policy semantics, full-netted provenance, source consistency, or the policy window cannot be established, the scope remains `POLICY_NOT_CONFIRMED` or `INCOMPLETE`; graph collection still runs.

`docs/database/bulk-ledger-track1-auxiliary-results-migration.sql` is an additive follow-up migration. It must be applied once after the existing BL-07 migration; it does not update old completed jobs or backfill them automatically.

The only Data-specific configuration is the existing internal Track 1 key, `ticket-defender.bulk-ledger-track1.bulk.policy-bundle-version`, and `ticket-defender.bulk-ledger-track1.bulk.storage-prefix`. The prefix must exactly equal Data `TRACK1_BULK_S3_PREFIX`: Backend uploads `<prefix>/<opaque objectKey>` while the manifest sends only `objectKey`. Without a real policy bundle or matching private, versioned storage prefix, registration is blocked; no version ID or key is rewritten.
