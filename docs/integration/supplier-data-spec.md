# 예매처 제공 데이터 명세

상태: 합성 개발 환경에서 API/CSV 계약을 검증하기 위한 초안. 실제 예매처 계약 체결, 실제 자료 수집, 사람 참여 실험을 승인하지 않는다.

## CSV 파일 계약

예매처는 회차별 파일을 나누지 않고 하나의 UTF-8 CSV를 제공한다. 첫 행은 헤더다. `SUPPLIER_CODE` 등록에서는 아래 필수 열로 공연과 회차를 식별하고, 파일의 공연/회차 메타데이터는 Backend 등록 요청에 전달한 값과 일치해야 한다.

| 열 | 필수 | 의미와 형식 | 근거 자료 | 보존/미제공 시 영향 |
| --- | --- | --- | --- | --- |
| `source_event_code` | 예 | 예매처 내 공연 코드, 128자 이내 | 예매처 공연 카탈로그 또는 정산/판매 내보내기 | 코드가 없으면 자동 매핑 불가. 테넌트 안에서만 식별한다. |
| `source_performance_code` | 예 | 예매처 내 회차 코드, 128자 이내 | 예매처 회차 카탈로그 또는 판매 내보내기 | 코드가 없으면 회차 멱등 등록 불가. |
| `event_title` | 예 | 공연명, 255자 이내 | 예매처 판매/공연 정보 | 기존 동일 코드의 명칭과 다르면 업데이트하지 않고 거절한다. |
| `performance_starts_at` | 예 | 회차 시작 시각, 오프셋 포함 ISO 8601 | 예매처 일정 정보 | 오프셋 없는 시각은 거절한다. |
| `per_account_limit` | 아니오 | 계정당 회차별 최대 구매 수, 양의 정수 | 예매 정책 화면 또는 정책 내보내기 | 없으면 한도 사실을 추정하지 않으며 기존 분석 대체 규칙을 유지한다. |
| `reservation_reference` | 예 | 예약/예매 참조번호 | 예약 기록 | 원문은 HMAC 처리 뒤 폐기한다. 계획상 예약 기록 보존기간을 고려해 제공 가능성만 확인한다. |
| `ticket_reference` | 예 | 티켓 참조번호 | 발권 기록 | 원문 보관 기능이 꺼져 있으면 HMAC만 저장한다. |
| `account_reference` | 예 | 예매처 내부 계정 식별자 | 계정/예약 연결 자료 | 계정 이름, 연락처 등 다른 식별자는 요청하지 않는다. 계정 값은 HMAC 또는 승인된 별도 암호화 기능으로 처리한다. |
| `purchased_at` | 예 | 구매 시각, 오프셋 포함 ISO 8601 | 구매/결제 기록 | 누락 또는 오프셋 부재는 거절한다. |
| `ticket_quantity` | 예 | 양의 정수 | 주문/티켓 내역 | `TICKET`이면 행당 1이어야 한다. |
| `quantity_unit` | 예(v2/v3) | `TICKET` 또는 `ORDER_LINE` | 예매처 내보내기 정의 | 의미가 없으면 행 수량의 해석이 불가능하다. |
| `ticket_status` | 예(v2/v3) | `ACTIVE`, `CANCELLED`, `REFUNDED` | 발권/취소 상태 | 취소와 환불 수량을 ACTIVE 구매와 혼합하지 않는다. |
| `source_version` | 예(v2/v3) | 예매처 원본 버전 또는 export 버전 | 내보내기 메타데이터 | 변경 피드의 출처 재현에 쓴다. |
| `seat_zone`, `seat_row`, `seat_number` | 아니오 | 좌석 구역/열/번호, 각 64자 이내 | 발권 좌석 정보 | 비어 있으면 좌석 근거가 없는 것으로 둔다. 외부 전달/로그에 행 단위로 노출하지 않는다. |
| `reserved_at` | 아니오 | 예약 생성 시각, 오프셋 포함 ISO 8601 | 예약 이력 | 없으면 예약 시점 분석 근거가 줄어든다. |
| `paid_at` | 아니오 | 결제 완료 시각, 오프셋 포함 ISO 8601 | 결제 승인 기록 | 없으면 결제 시점 분석 근거가 줄어든다. |
| `cancelled_at` | 아니오 | 취소 시각, 오프셋 포함 ISO 8601 | 취소/청약철회 기록 | 취소 시점의 합성 분석만 가능하다. 기본 분석 요청의 별도 취소 목록에는 보내지 않는다. |
| `account_created_at` | 아니오 | 계정 생성 시각, 오프셋 포함 ISO 8601 | 계정 생성 이력 | 없으면 계정 생성 시점 근거가 없다. |

추가 선택 원본 신호(`device_reference`, `ip_reference`, 결제/연락처 열)는 기존 v3 원본 수신 문서의 열 계약을 그대로 따른다. 필요 근거가 승인되지 않으면 전달하지 않는다. Backend는 원문 신호를 응답이나 오류 메시지에 포함하지 않는다.

## 개인정보 최소화 및 보존 조건

- 실 예매처 도입 전에는 각 열의 제공 근거, 목적, 접근 역할, 저장 위치, 파기 시점, 예매처의 위탁/제공 계약을 별도로 확인한다. 이 문서는 현행 법률에 대한 법률 의견이 아니다.
- 프로젝트 요구사항에서 예약/결제/취소 자료는 최대 5년 보유 여부, 접속 IP/기기 신호는 최대 3개월 보유 여부를 확인 대상으로 제시한다. 실제 보존 기간은 예매처별 계약과 현행 법령 검토 결과 중 더 짧은 필요 기간을 적용하고, 확인 전 실데이터를 받지 않는다.
- 티켓 Defender에는 예약 원문 CSV를 영구 보관하지 않는다. 업로드 원본은 private staging 수명주기에 따라 삭제하고, 시스템에는 필요 최소한의 HMAC, 합성 환경에서 허용된 암호문, 분석 결과만 남긴다.
- 연락처, 배송지, 결제 정보, 환불 계좌, 원 IP/기기 식별값은 이 CSV 계약으로 복원 가능하게 보관하지 않는다. 고위험 신호는 목적별 HMAC 사용만 허용한다.
- 동일 CSV의 전체 바이트 SHA-256은 원본 내용이 아닌 파일 동일성 확인값이다. 행 단위 해시/오류에는 원본 필드를 넣지 않는다.
- 실험용 원본-정답 대응표는 별도 실험자 권한과 저장소 외부 격리 보관 대상이며 제품 CSV, Backend DB, Git 저장소에 포함하지 않는다.

## 실패와 재시도

- 업로드 전체의 UTF-8, 헤더, 행 개수, 코드/메타데이터 일치를 먼저 검증한 후 공연/회차를 생성한다.
- 검증 실패 시 공연/회차, 구매 정책, 원장 공개 상태에 부작용이 없어야 한다.
- 같은 테넌트/코드 재업로드는 기존 UUID를 재사용한다. 다른 테넌트의 같은 코드는 별도 UUID 공간으로 처리한다.
- 기존 공연명, 회차 시작 시각, 공급자 확인 한도를 입력값으로 덮어쓰지 않는다. 서로 충돌하면 새 자료를 반영하지 않고 검토용 오류 코드만 반환한다.
